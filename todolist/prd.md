# PRD: 오늘의 할일 (Today's To-Do) 웹페이지

- 문서 버전: v0.1 (설계 초안)
- 작성일: 2026-11-02
- 상태: 설계 완료 / 구현 전

---

## 1. 개요

### 1.1 배경
하루 단위로 해야 할 일을 빠르게 적고, 완료 여부를 체크하며, 하루가 끝났을 때 얼마나 해냈는지 한눈에 확인할 수 있는 가벼운 웹페이지가 필요하다. 복잡한 프로젝트 관리 도구가 아니라 "오늘" 한 가지에 집중한다.

### 1.2 목표
- 3초 안에 할 일을 추가할 수 있다.
- 오늘 할 일과 진행률을 한 화면에서 파악할 수 있다.
- 별도 설치·로그인 없이 브라우저만으로 동작한다.
- 새로고침하거나 브라우저를 닫았다 열어도 데이터가 유지된다.

### 1.3 비목표 (이번 범위에서 하지 않는 것)
- 회원가입/로그인, 서버 동기화, 여러 기기 간 공유
- 팀 협업, 담당자 지정, 댓글
- 반복 일정, 캘린더 연동, 푸시 알림
- 장기 프로젝트 관리 (칸반, 하위 작업 트리 등)

## 2. 대상 사용자 및 시나리오

### 2.1 페르소나
- **직장인/학생**: 아침에 오늘 할 일을 5~10개 적고, 하루 동안 하나씩 체크한다.
- **간단함을 선호하는 사용자**: 앱 설치 없이 브라우저 탭 하나로 해결하고 싶다.

### 2.2 핵심 사용자 시나리오
1. 아침에 페이지를 열면 오늘 날짜와 빈 목록(또는 어제 못 끝낸 일 안내)이 보인다.
2. 입력창에 할 일을 입력하고 Enter → 목록에 즉시 추가된다.
3. 일을 끝내면 체크박스를 클릭 → 취소선 처리되고 진행률이 올라간다.
4. 잘못 적은 항목은 더블클릭해 수정하거나 삭제한다.
5. 저녁에 진행률(예: 7/9 완료, 78%)을 확인한다.
6. 다음 날 페이지를 열면 어제 미완료 항목을 오늘로 가져올지 선택할 수 있다.

## 3. 기능 요구사항

우선순위: **P0** = MVP 필수, **P1** = MVP 직후, **P2** = 추후 검토

### 3.1 할 일 관리 (P0)
| ID | 기능 | 설명 | 수용 기준 |
|----|------|------|-----------|
| F-01 | 할 일 추가 | 상단 입력창에 텍스트 입력 후 Enter 또는 "추가" 버튼 | 공백만 입력 시 추가되지 않음. 최대 200자. 추가 후 입력창 비워지고 포커스 유지 |
| F-02 | 완료 토글 | 체크박스로 완료/미완료 전환 | 완료 시 취소선 + 흐린 색, 진행률 즉시 갱신 |
| F-03 | 수정 | 항목 텍스트 더블클릭(모바일: 수정 버튼) → 인라인 편집 | Enter 저장, Esc 취소, 빈 값으로 저장 시 원래 값 유지 |
| F-04 | 삭제 | 항목 hover 시 나타나는 삭제 버튼 | 삭제 후 5초간 "실행 취소" 토스트 제공 |
| F-05 | 데이터 유지 | 모든 변경 사항을 브라우저 localStorage에 자동 저장 | 새로고침/재방문 시 동일 상태 복원 |

### 3.2 오늘 화면 (P0)
| ID | 기능 | 설명 | 수용 기준 |
|----|------|------|-----------|
| F-06 | 오늘 날짜 표시 | 헤더에 "2026년 11월 2일 (월)" 형식 | 사용자 로컬 시간대 기준 |
| F-07 | 진행률 | "완료 n / 전체 m" 텍스트 + 진행 바 | 항목이 0개면 "오늘 할 일을 추가해 보세요" 빈 상태 메시지 |
| F-08 | 필터 | 전체 / 진행 중 / 완료 탭 | 선택한 필터는 새로고침 후에도 유지 |
| F-09 | 완료 항목 일괄 삭제 | "완료 항목 지우기" 버튼 | 완료 항목이 없으면 비활성화. 확인 후 실행 |

### 3.3 날짜 전환 처리 (P1)
| ID | 기능 | 설명 | 수용 기준 |
|----|------|------|-----------|
| F-10 | 미완료 이월 | 날짜가 바뀐 뒤 첫 접속 시, 전날 미완료 항목이 있으면 배너로 "어제 못 끝낸 n개를 오늘로 가져올까요?" | "가져오기" 선택 시 해당 항목을 오늘로 **이동**(`date`를 오늘로 변경, `carriedFrom`에 원래 날짜 기록, "이월" 배지 표시). 전날 목록에서는 사라짐. "무시" 시 그대로 둠 |
| F-11 | 지난 기록 보기 | 헤더의 이전/다음 날짜 화살표로 과거 날짜 목록 조회 | 과거 날짜는 읽기 + 완료 토글만 가능, 추가는 오늘만 |

## 6. 데이터 설계

### 6.1 데이터 모델
```ts
interface Todo {
  id: string;          // crypto.randomUUID()
  text: string;        // 1~200자
  done: boolean;
  important: boolean;  // F-12
  date: string;        // "YYYY-MM-DD" (로컬 기준, 소속 날짜)
  order: number;       // 정렬 순서
  carriedFrom?: string;// 이월된 경우 원래 날짜
  createdAt: number;   // epoch ms
  completedAt?: number;
}

interface AppState {
  version: 1;          // 스키마 버전 (마이그레이션용)
  todos: Todo[];
  settings: {
    filter: "all" | "active" | "done";
    theme: "system" | "light" | "dark";
  };
  lastOpenedDate: string; // 이월 판단용 "YYYY-MM-DD"
}
```

### 6.2 저장 방식
- localStorage 키: `todolist:v1`
- 변경 시마다 전체 상태를 JSON 직렬화하여 저장 (데이터 규모가 작으므로 충분)
- 로드 시 파싱 실패하거나 `version` 불일치 시 기본값으로 시작하고, 원본은 `todolist:backup`에 보존

### 6.3 날짜 처리 규칙
- "오늘"은 사용자 로컬 시간 자정 기준
- 페이지가 열려 있는 상태에서 자정이 지나면, 다음 사용자 조작 또는 탭 포커스 시 날짜를 재계산
- 지난 기록은 기간 제한 없이 보관하며 자동 삭제하지 않음 (정리는 사용자가 F-18로 직접 실행)
- 저장 시 용량 초과(`QuotaExceededError`)가 나면 "저장 공간이 부족합니다. 백업 후 오래된 기록을 정리하세요" 경고 표시

## 7. 기술 설계

### 7.1 기술 스택 (권장)
| 영역 | 선택 | 이유 |
|------|------|------|
| 구조 | HTML5 | 단일 페이지 |
| 스타일 | CSS (커스텀 프로퍼티) | 다크모드 토큰 전환이 간단, 빌드 불필요 |
| 로직 | Vanilla JavaScript (ES Modules) | 기능 규모가 작아 프레임워크 불필요, 의존성 0 |
| 저장소 | localStorage | 서버 없이 영속화 |
| 배포 | 정적 호스팅 (GitHub Pages 등) 또는 로컬 파일 | 빌드 단계 없음 |

> 대안: 이후 기능이 커지면 React + Vite로 전환 가능하도록 `store`(상태)와 `view`(렌더링)를 분리해 둔다.

### 7.2 폴더 구조 (예정)
```
todolist/
├── prd.md            # 본 문서
├── index.html        # 마크업 골격
├── css/
│   └── style.css     # 토큰, 레이아웃, 컴포넌트 스타일
└── js/
    ├── main.js       # 진입점: 초기화, 이벤트 바인딩
    ├── store.js      # 상태 관리 + localStorage 입출력
    ├── view.js       # DOM 렌더링
    └── date.js       # 날짜 유틸 (오늘 키, 포맷, 이월 판단)
```

### 7.3 아키텍처
```
[사용자 이벤트] → main.js (핸들러)
                     │ action 호출 (addTodo, toggleTodo, ...)
                     ▼
                 store.js ──저장──▶ localStorage
                     │ 상태 변경 알림 (subscribe)
                     ▼
                 view.js → DOM 다시 그리기
```
- 단방향 데이터 흐름: 이벤트 → 상태 변경 → 렌더링
- store 공개 API: `getState()`, `subscribe(fn)`, `addTodo(text)`, `toggleTodo(id)`, `editTodo(id, text)`, `deleteTodo(id)`, `restoreTodo(todo)`, `clearDone()`, `toggleImportant(id)`, `reorder(id, newIndex)`, `carryOver(fromDate)`, `setFilter(f)`, `setTheme(t)`
- 렌더링은 목록 전체 재생성으로 시작(항목 수가 적음), 성능 문제 시 key 기반 부분 갱신

## 11. 결정 사항
- **이월 방식: 이동으로 확정 (2026-11-02).** 미완료 항목을 복사하지 않고 오늘로 옮기며, `carriedFrom`으로 원래 날짜를 추적한다. 같은 일이 여러 날짜에 중복되지 않도록 하기 위함.

- **보관 정책: 무기한 보관, 자동 삭제 없음 (2026-11-02).** 할 일 하나가 수백 바이트 수준이라 하루 10개씩 써도 1년에 1~2MB 정도로, localStorage 한도(보통 5MB) 안에 여러 해 들어간다. 사용자 모르게 기록이 사라지는 일을 막기 위해 정리는 수동(F-18)으로만 하고, 용량 초과 시 경고로 안내한다.
- **JSON 백업/복원: 도입, P1 (2026-11-02).** localStorage는 브라우저 데이터 삭제나 기기 변경 시 사라지므로, 서버 없이 데이터를 지킬 유일한 수단으로 백업 기능(F-17)을 제공한다.
